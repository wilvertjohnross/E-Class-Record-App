# KLAS v1.4.31 stabilization audit

Date: 2026-09-24. Review only: no application source, installed records, signing keys, or Git history changed.

## Baseline and conclusion

Authoritative baseline: `KLAS-v1.4.31-source.zip` from the existing outputs folder, extracted independently to an audit directory. SHA-256: `A1605C7FCC197F58520FFBBB0BC9F16025393C5A709B67C0AC1B61A045DC1E3A`. All 68 extracted files were checked against the archive after the review. The Git checkout remains clean.

**Checkpoint result: continue with a targeted stabilization patch; do not treat v1.4.31 as fully cleared for imports and official grading outputs.** No Critical finding was confirmed. Ordinary navigation, default grading controls, common profile flows, and the signed update package passed the checks below. Defects include inherited behavior as well as the consequences of locking WW/PT controls; they are not all new regressions introduced in v1.4.31.

File references below are relative to the ZIP root, with one-based source line numbers. Findings are ordered by recommended stabilization priority. No grading policy or transmutation table change is recommended.

## Prioritized findings

### 1. Incomplete backups can replace working data and then break rendering
- **Classification:** Data-risk. **v1.4.32:** Yes, release blocker for import stability.
- **Location:** `app/app.js:3706`, `validateBackupForImport`; desktop/browser backup handlers at lines 3779–3808. Also `main.js:80`, `parseAndValidateAppState`, and renderer `loadState` at line 527.
- **Wrong:** Category validation is conditional on categories being present. It does not require complete WW/PT/EXAM or score structures. A backup containing `classes.c = {id:'c',meta:{},students:[]}` passes renderer validation. The handlers assign it to APP and call save before a successful render has been established.
- **Evidence:** Synthetic backup accepted; Class Setup then throws `Cannot read properties of undefined (reading 'WW')`.
- **Why it matters:** A malformed or incomplete backup can replace usable data and enter the save/recovery cycle. Main-process validation is also weaker than the renderer in some areas, including adviser records. Recovery files reduce risk but are not a substitute for validating before replacement.
- **Fix:** Normalize explicitly supported legacy formats on a clone, validate required domains and nested structures, and reject unrepairable input before replacing APP. Preserve a pre-import snapshot and await the save result. Align main/renderer validation. Do not silently turn a corrupt existing file into an empty successful import.

### 2. Blank ECR HPS cells are converted into zero
- **Classification:** Data-risk. **v1.4.32:** Yes.
- **Location:** `app/app.js:2411`, `applyOfficialEcrImport`, especially `applyHps` around line 2429.
- **Wrong:** `Number('')` and `Number(null)` are zero. The HPS assignment does not skip blank values as the weight assignment does.
- **Evidence:** An import payload with five blank WW HPS values changes existing `[50,30,30,55,30]` to `[0,0,0,0,0]`.
- **Why it matters:** Existing components become inactive and grades can change or disappear. The flexible importer represents unread/empty numeric cells as blank strings.
- **Fix:** Distinguish missing HPS from an explicitly entered numeric zero. Preserve current HPS with a warning, or reject incomplete HPS before applying the import. Test blank, null, absent and explicit-zero values separately.

### 3. ECR imports bypass cross-term HPS safeguards
- **Classification:** Data-risk. **v1.4.32:** Yes.
- **Location:** `app/app.js:2411`, `applyOfficialEcrImport`; compare `bindCategoryEditorEvents` around line 1299 and `validateGradingConfiguration` at line 2560.
- **Wrong:** Categories/HPS are shared across all terms, but an ECR import directly changes them without the manual HPS editor's existing-score check.
- **Evidence:** Importing Term 2 HPS of 10 while Term 1 has a WW1 score of 50 leaves that old score intact but invalid. Term 1 WW percentage changes from 25.64 to 32.26, and validation reports score 50 exceeding HPS 10.
- **Why it matters:** Importing one term can alter earlier computations and make earlier official forms fail validation.
- **Fix:** Preflight changes against scores in every term before mutation. Reject incompatible changes, and explicitly disclose other cross-term recalculation impacts. A future per-term configuration migration is a separate design decision, not required for this stabilization patch.

### 4. Failed SF1 imports leave partial mutations
- **Classification:** Data-risk. **v1.4.32:** Yes.
- **Location:** `app/app.js:1384`, `applyOfficialSf1Import`, and caller `importOfficialSf1IntoClass` at line 1450.
- **Wrong:** Metadata and imported status are written before the learner loop. New learners are pushed directly into the live class. Capacity checks run before removals for the remove-absent option. Failure does not roll back.
- **Evidence:** With 999 existing learners and two new SF1 learners, remove-absent import throws at 1,000, but leaves a new learner, changed section and `sf1SourceStatus='imported'` in memory.
- **Why it matters:** A failed operation can change the adviser gate and roster; a later save can persist those changes. A replacement that would ultimately contain two learners fails because the temporary combined roster reaches the limit.
- **Fix:** Build and validate the final roster and metadata on a clone, calculate final capacity after the chosen merge/removal policy, then commit once. An unsuccessful import must leave all domains byte-for-byte unchanged.

### 5. Final-grade descriptors are derived from a second transmutation
- **Classification:** Functional bug. **v1.4.32:** Yes.
- **Location:** `app/app.js:743`, `studentFinalResult`; displayed by `renderFinal` at line 2868.
- **Wrong:** The whole-number average of already-transmuted term grades is passed to `transmute` again for its band, while the displayed numeric final remains the average.
- **Evidence:** Three term grades of 75 produce final 75 with `Benchmarking`; the app's own `bandFor(75)` gives `Connecting`.
- **Why it matters:** The descriptor contradicts the numeric grade and the existing band thresholds.
- **Fix:** Use `bandFor(final)` for the descriptor. Keep the numerical final, averaging, category calculations and transmutation table unchanged. This is inherited behavior, not a new formula regression.

### 6. Legacy WW/PT configurations can be stranded outside official templates
- **Classification:** Functional bug. **v1.4.32:** Yes.
- **Location:** `app/app.js:1247`, `renderCategoryEditor`; `applyOfficialEcrImport:2411`; `validateGradingConfiguration:2560`; `officialEcrPayload:2616`.
- **Wrong:** Preserved legacy counts cannot be adjusted because add/remove controls are gone, while official import/output requires exactly 5 WW and 3 PT. Legacy custom WW/PT modes are also retained while their item-weight controls are hidden.
- **Evidence:** A six-WW class remains six after rendering and has no count controls; official validation rejects it. Legacy custom modes survive reload in the comparison tests.
- **Why it matters:** Data is preserved, but users can lose access to official ECR/GS workflows. Some legacy configurations cannot be repaired through the available UI.
- **Fix:** Retain fixed defaults for new classes. Add a bounded legacy compatibility path with a clear explanation and explicit, backed-up migration/mapping. Do not truncate scored items or silently change custom weighting. If migration is deferred, retain a limited legacy-only repair control.

### 7. Simple examination mode conflicts with official-output validation
- **Classification:** Functional bug. **v1.4.32:** Yes.
- **Location:** `app/app.js:2616`, `officialEcrPayload`; `main-extension.js:771`, `validatePayload`.
- **Wrong:** Renderer supports simple examinations, but the official payload omits mode and the backend always enforces custom examination weights.
- **Evidence:** Simple EX mode with its first HPS set to zero passes renderer validation; backend rejects it because the inactive item's retained custom weight is nonzero. Other invalid retained weights can likewise block simple mode.
- **Why it matters:** A valid visible setup can unexpectedly fail official ECR/GS creation with controls that are hidden in the chosen mode.
- **Fix:** Carry mode explicitly and validate it consistently in both layers. Verify that examination component columns in both templates agree with the selected mode; do not merely remove the error check.

### 8. Compact SF1 headers are contaminated by the first learner row
- **Classification:** Functional bug. **v1.4.32:** Yes.
- **Location:** `flex-importers.js:193`, `labelWindow`; `detectSf1Header:244`; `parseSf1Sheet:252`.
- **Wrong:** Header detection always concatenates a cell with the next row. Recognized one-row headers can become unrecognizable when learner data starts immediately underneath.
- **Evidence:** Synthetic matrix with `LRN | Name | Sex` followed immediately by one valid learner returns no recognized roster. The same matrix with two blank rows below the header recognizes that learner.
- **Why it matters:** A reasonable compact SF1-compatible layout is rejected despite readable identifiers and sex values.
- **Fix:** Evaluate single-row headers before bounded multi-row combinations; never blend probable learner rows into a header. Preserve confidence thresholds, LRN validation, duplicate warnings and conservative sex handling.

### 9. Browser-only recovery failure is reported as successful save
- **Classification:** Data-risk, lower priority for the installed desktop target. **v1.4.32:** Yes, small defensive fix.
- **Location:** `app/app.js:567`, `saveState`.
- **Wrong:** A localStorage write exception is logged, then the no-desktop-API branch returns `{ok:true,localOnly:true}` and displays Saved locally.
- **Evidence:** Injected quota failure returned success and a saved status despite no successful storage write.
- **Why it matters:** Browser previews/fallback use can lose records or a profile after reload. This reproduction does not establish silent failure in normal Electron disk saves, which have a separate failure status.
- **Fix:** Track the local write outcome and report failure when no persistence destination succeeds. Ensure profile saving does not close as successful in that case.

### 10. Update-folder selection is applied after the startup scan
- **Classification:** Functional bug / operational limitation. **v1.4.32:** Document now; fix only with a bootstrap-compatible plan.
- **Location:** `thread-updater.js:166`, `initialize`; `main.js` startup sequence around line 736; `main-extension.js:2408`, `register`.
- **Wrong:** Bootstrap initialization scans Downloads before the extension redirects Downloads to the configured outputs directory. The path is also specific to this computer/user.
- **Evidence:** Source-order inspection; not a new timed restart experiment. The running watcher uses the redirected directory afterward.
- **Why it matters:** An update placed in outputs while the app is closed may only stage after launch and require another restart. The configured path is unsuitable as a general distributed default. This helps explain an apparent stale-UI update state without proving any particular user incident.
- **Fix:** Keep the requested development directory on this machine, but establish one explicit update-directory setting before the scan. Changing main.js/thread-updater.js requires a new bootstrap or a verified extension-compatible approach: simply putting those files in a runtime payload does not replace the executing bootstrap.

### 11. Removed startup control still affects persisted profiles
- **Classification:** UI inconsistency. **v1.4.32:** Yes.
- **Location:** `app/welcome.js:12`, `welcomeInitialTab`; current `renderWelcome` no longer includes the skip control.
- **Wrong:** A saved `settings.welcome.skipStartup=true` still bypasses Welcome, with no visible control to reverse it.
- **Why it matters:** Users upgraded from an earlier welcome version can see a different startup experience and cannot reset the preference through the app.
- **Fix:** Since removal was requested, explicitly retire/migrate that setting so Welcome is the default, or retain a settings-only switch if approved. Do not restore the removed bottom strip without approval. Verified by source inspection, not a new startup-skip interaction test in this audit.

### 12. Some guidance still refers to removed navigation
- **Classification:** Minor cleanup. **v1.4.32:** Yes, if kept narrowly textual.
- **Location:** `app/app.js:2868`, `renderFinal` empty state; `classRecordLinkStatus` around line 276 and other older workflow descriptions.
- **Wrong:** Empty-state guidance says Subject Teacher Controls → Classes, while the current sidebar uses Class Overview → Learner Roster. Some older linking descriptions predate the separated adviser workflow.
- **Why it matters:** Users are directed to labels that no longer exist or can misunderstand which grade domain feeds official forms.
- **Fix:** Update guidance to existing routes and the established role separation. Keep behavior unchanged. Source-inspected.

## Proposed v1.4.32 stabilization scope

1. Make backup and SF1 imports transactional, with validated candidate state and pre-operation recovery. Add failed-import/no-mutation tests.
2. Fix missing-HPS conversion and guard cross-term changes during ECR imports.
3. Correct final descriptor selection without changing numeric results or policy tables.
4. Resolve examination mode agreement between renderer and official-output engine.
5. Provide a safe legacy configuration recovery path without deleting scores or silently converting weighting modes.
6. Repair compact SF1 header detection while retaining bounded import behavior.
7. Fix failed-save status, retire the orphaned startup preference, and correct obsolete route text.
8. Document update staging/restart behavior. Treat any bootstrap replacement as an explicit separate release decision.

Release gates: the reproductions above must fail safely or produce corrected results; existing numerical grading vectors must remain unchanged except where previously corrupted inputs are rejected. No layout redesign, transmutation-policy change, or silent data migration.

## What was actually tested

All live test records were synthetic. Browser tests used headless Microsoft Edge against the separately extracted ZIP, not the mutable development folder.

- Loaded a synthetic v1.4.8 state and compared encoded term/final results with that earlier baseline.
- Compared 240 simple/custom category vectors; independently checked expected automatic 70% and custom 65% results. Tested all existing transmutation-table endpoints.
- Checked 5/3 defaults, read-only item names, absence of WW/PT count controls, editable/persisted HPS, rejection below existing scores, raw-score boundaries/blanks, category totals, EX mode toggles/weights and add/remove.
- Created, duplicated, selected and deleted synthetic teaching classes. Opened all three term views and Final Grades.
- Checked Class Overview nested routes and keyboard expansion/collapse.
- Tested profile popup Close/Escape, name/title/photo/Employee ID persistence, greeting periods, live clock, Continue navigation, removed strips and bundled banner loading.
- Checked light/dark welcome layouts at 320, 390, 980 and 1440 widths, and Class Setup layouts at ten widths from 320 to 1920. Checked reduced-motion and print CSS behavior. This is not a formal contrast-ratio or full accessibility audit.
- Confirmed unconfigured adviser routes return to the inline SF1 gateway. Checked that subject mutations do not alter the normalized adviser fixture; SF9 reads the adviser's stored summary grade.
- Checked SF2 P/A/L/C cycling, legacy T normalization, presence/absence/tardy totals and transfer to SF9 for a four-day fixture.
- Exercised bounded SF1 parser functions with valid learner, duplicate LRN, invalid LRN, unknown sex, and compact header matrices. This is not an exhaustive real-workbook parser corpus.
- Built ECR, GS and SF2 XLSX buffers from synthetic payloads and opened their ZIP structures. Checked ECR unused-row hiding and preservation of the female divider. This does not prove Excel/PDF appearance.
- Exercised the main-process safe-write function against disposable files: valid writes, previous-copy preservation and invalid-write rejection.
- Verified the existing user-signed v1.4.31 package using the embedded Ed25519 public key; verified all nine payload hashes; rejected a modified signed manifest. No private key accessed and no package signed during this review.
- Compared installed app.asar bootstrap v1.1.5 with the ZIP: main.js, preload.js, thread-updater.js, sf1-parser.js and ECR/GS/SF2 templates match byte-for-byte; public keys match. This is compatibility evidence, not a fresh installation test.
- Verified nine-file unsigned payload/source parity and all 68 extracted source files against the ZIP. Checked archive paths/text for private-key material and excluded-file indicators; none found. This is not a comprehensive secret-scanner or malware assessment.

The unchanged-baseline grading comparisons establish no detected accidental changes in those numerical paths. They do not establish that every inherited calculation is correct: the final-band defect is a concrete counterexample.

## Inspected, not fully exercised

- Full main-process recovery selection, failed disk-save handling, update-directory scan order, extension loading, IPC action allowlist and sender checks.
- Adviser Summary import matching/range logic; SF9 read-only grade flow, attendance synchronization, logo order/70.2px size and signatory structure.
- SF1 legacy-XLS renderer, merged-cell handling, landscape/one-page-wide settings and vertical pagination; Excel process/cache lifecycle.
- Real SF1/ECR workbook variations, full print pagination, actual printers, and all attendance calendar edge cases were not exhaustively tested.
- SF2 capacity is explicitly limited to 21 male/25 female learners and 25 school days per page. Overflow is intentionally rejected; multi-page overflow is a known limitation, not a newly introduced regression. ECR/GS have fixed section capacities. SF5/SF10 remain marked as future functionality.

## Short Windows hands-on checklist

1. On a disposable Windows data profile, install/stage the signed patch through the actual installed app, restart, confirm effective/staged versions and test detection both while open and while closed.
2. With the real Excel version, preview/export SF1, ECR, GS and SF2 using approved synthetic workbooks. Check wide columns, merged headers, unused-row hiding, multi-page breaks, final rows and preview-cache refresh after edits.
3. Preview and print SF9 for a synthetic learner with long names, a custom school logo and all signatories. Confirm logo order/size, clipping, page breaks and physical/printer-PDF scaling.
4. Exercise Windows file dialogs and disk-denied scenarios for save/export/import; restart and verify recovery/status behavior on the disposable profile.
5. At common Windows display scaling settings (100%, 125%, 150%), use keyboard and mouse to inspect sidebar scrolling, popup focus, profile-photo sizing and full-screen restore; inspect actual light/dark button legibility.
